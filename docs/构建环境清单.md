# 构建环境清单（要什么／从哪拿／放哪／怎么验）

> 配套：[BUILD.md](../BUILD.md)（命令级步骤）、[build.conf.example](../build/build.conf.example)（路径配置示例）。
> 默认路径：工具链＝`<源码树>/工具链`，物料＝`<源码树>/物料`（都可用 `build.conf` 或环境变量改）。
> 本仓库**不含**下表任何二进制/第三方件。
> ★**2026-10-13（60 号单）：下表的「从哪拿」已逐条在设备上实测**（命令＋输出见各表末注与「重导配方」）。
> 与 59 版的关系：59 版写的拿法基本都对（`pkg install aapt2`／build-tools 的 `lib/apksigner.jar`）；本单把**版本号钉准**（ECJ **3.13.102**／D8 **9.2.4-dev**／aapt2 **2.20-android-16.0.0_r4**／apksigner **0.9**），并把四件从「未实测」变成**实测**（其中 2 件逐字节一致）。

## 一、设备侧工具链（工具链/）

| 件 | 要什么 | 从哪拿（怎么造） | 放哪 | 怎么验 |
|---|---|---|---|---|
| `bin/aapt2` | **Termux 版** aapt2（官方 SDK 里的是 x86 Linux 版，在 Android 上跑不了） | Termux 里 **`pkg install aapt2`**（版本 16.0.0.4-3；`aapt2` 是 `aapt` 包的**子包**），把 `$(command -v aapt2)` 与 `$PREFIX/lib` 下它依赖的那批 `.so` 一起拷出（见下） | `工具链/bin/aapt2` ＋ `lib*.so` 同目录 | `LD_LIBRARY_PATH=工具链/bin 工具链/bin/aapt2 version` |
| `lib/android.jar` | Android SDK **platform-35** | 官方 `platform-35_r0x.zip` 解出的 `android-35/android.jar` | `工具链/lib/android.jar` | 文件在即可（aapt2 link `-I` 用） |
| `dex/ecj.dex` | Eclipse ECJ **3.13.102**（3.21+ 初始化要读 JDK 模块系统 `jrt`，Android 上必崩——沿用 59 单实测） | Maven Central `org.eclipse.jdt:ecj:3.13.102` → **先解出 jar 内非 class 资源** → d8 转 dex | `工具链/dex/ecj.dex`＋资源目录 `工具链/ecj-res/` | build2.sh 第 3 步能编译出 class |
| `dex/d8.dex`＋`dex/d8-2.dex` | R8/D8（**9.2.4-dev，build engineering**） | Android SDK **build-tools 37.0.0** 的 `lib/d8.jar` → d8 转 dex（**太大自动出两个 dex**，一起放 classpath） | `工具链/dex/` | build2.sh 第 4 步能出 dex |
| `dex/apksigner.dex` | apksigner（命令行） | build-tools 的 **`lib/apksigner.jar`** → d8 转 dex（★Maven 的 `com.android.tools.build:apksig` 只有库、没有命令行） | `工具链/dex/apksigner.dex` | `…ApkSignerTool verify` 能跑 |
| `dex/buildtool.dex` | **本仓库自带源码 `工具/BuildTool.java`** | ECJ 编译 → d8 `--min-api 24` 转 dex | `工具链/dex/buildtool.dex` | 空参跑出 `usage: BuildTool …` |
| `ecj-res/` | ECJ 的非 class 资源（`messages*.properties`、`parser*.rsc`） | 从 ECJ jar 里解出来（`unzip -x '*.class'`） | `工具链/ecj-res/` | 缺了第 3 步会失败（59 单实测 rc=137） |
| `debug.p12`（可选） | 调试签名回退 | `keytool` 自造 | `工具链/debug.p12` | 签名段失败时的回退提示 |

### 出处与重现性（60 号单实测底账）

| 件 | 出处结论（怎么查出来的） | 照配方重造的结果 |
|---|---|---|
| `bin/aapt2` | **Termux `aapt2` 包**（＝`aapt` 包的子包：`packages/aapt/aapt2.subpackage.sh` 里 `TERMUX_SUBPKG_INCLUDE="bin/aapt2"`、`TERMUX_SUBPKG_DEPENDS="abseil-cpp, libprotobuf"`，正对上现役 `DT_NEEDED` 的 `libabsl_*`／`libprotobuf`；两包同为 16.0.0.4-3，`aapt2` deb 963,912 B／Installed-Size 3540 KB≈现役二进制 3,594,152 B）：二进制内嵌构建路径 `/home/builder/.termux-build/aapt/src/vendor/base/tools/aapt2/…`；`termux-packages/packages/aapt/build.sh` 写的是 `TERMUX_PKG_VERSION=16.0.0.4`（源＝`termux/android-build-tools` 16.0.0.4 分支）；`aapt2 version` 输出 **`Android Asset Packaging Tool (aapt) 2.20-android-16.0.0_r4`**（对上 AOSP `android-16.0.0_r4`） | ★**能跑**：同一份二进制拷到 `/data/local/tmp` 后 `aapt2 version` 正常；拿它**真 link** 出一个 1207 B 的 apk，badging 读回 `package=test.selfmade／minSdk 30／targetSdk 35／compileSdk 35` |
| `bin/lib*.so` | 就是上面那批依赖的传递闭包：实测 `readelf -d aapt2` 的 `DT_NEEDED`＝`libfmt.so`／`libz.so.1`／`libpng16.so`／`libexpat.so.1`／`libprotobuf.so`／`libabsl_hash.so`／`libutf8_validity.so`／`libc++_shared.so`（＋`libdl`／`libc`）；Termux 包的依赖表写的是 `fmt, libc++, libexpat, libpng, libzopfli, zlib` | ★同上（现役 bin/ 里 100+ 个 `.so` 即此批的传递闭包；全拷 `$PREFIX/lib` 下同名文件即可） |
| `lib/android.jar` | **API 35**（Android 15）：`android/os/Build$VERSION_CODES` 里有 `VANILLA_ICE_CREAM`（35）**没有** `BAKLAVA`（36）；类文件版本＝52（Java 8 stub）；打包器 `soong_zip`；14,488 条目／47,358,926 B | 从官方 platform-35 包取（本单未重下，仅指纹比对） |
| `dex/ecj.dex` | **Maven Central `org.eclipse.jdt:ecj:3.13.102`**：现役 `-version`＝`v20180330-0919, 3.13.102`，与该 jar 转出来的 dex 输出**逐字相同** | ★**能造**：`ecj-3.13.102.jar`（2.6 MB，sha256 `e6b93833…b9be3`）→ `d8 --min-api 24` → 2,771,188 B（现役 2,771,216 B，**差 28 B，非逐字节**）→ 用这份自造 ECJ **真编出 `Hello.class`**（419 B） |
| `dex/d8.dex`＋`dex/d8-2.dex` | **build-tools 37.0.0 的 `lib/d8.jar`**：现役 dex 里内嵌构建标记 `R8_9.2.4-dev_ca5b565a5c7da61f18c57930a2823deaa7db40f41bc4509a15d64fc6a8b340be`，与 r37 的 `d8.jar` 内**完全同一个**；`--version`＝`D8 9.2.4-dev (build engineering)` | ★**能造**：`d8.jar`（20.5 MB，sha256 `a26ee562…637d`）→ 现役 d8 → dex；得到 `classes.dex` 2,877,692 B＋`classes2.dex` 8,519,828 B（**classes2.dex 与现役 `d8-2.dex` 逐字节一致**，classes.dex 差 28 B）。自造 d8 再跑 `--version` 得同一串，并**用它把官方 ecj 转成 dex**（自举成功） |
| `dex/apksigner.dex` | **build-tools 37.0.0 的 `lib/apksigner.jar`**：★Maven 的 `com.android.tools.build:apksig` 只有类库——8.7.3 实测 267 个 class、**0 个 `com/android/apksigner`**，命令行不在 Maven；build-tools 的 `lib/apksigner.jar` 里才有（`USAGE: apksigner sign …`） | ★**能造**：`apksigner.jar`（1.18 MB，sha256 `2defad21…4180`）→ d8 `--min-api 24` → 1,054,824 B（现役 1,054,856 B，**差 32 B**），跑 `ApkSignerTool --version`＝`0.9` |
| `dex/buildtool.dex` | **本仓库 `工具/BuildTool.java`**（源码就在仓库里） | ★**能造且逐字节一致**：自造 ECJ 编 → d8 `--min-api 24` → 5,056 B，`cmp` 与现役**完全相同**（sha256 `9eb9dce1…dd537`），空参跑出 `usage: BuildTool <baseApk> <outApk> <dexCsv> [jniDir|-]` |
| `ecj-res/` | **就从 ECJ jar 里解出来的非 class 文件**：`unzip -o ecj-3.13.102.jar -x '*.class'` ＝ 69 个文件，与现役 `ecj-res/` **`diff -rq` 完全一致** | ★能造（同上，一条 unzip） |

### 结论：能不能从零重造

- **七个件全部「能造」**：aapt2＋依赖 so（Termux 装包）、android.jar（官方 SDK 包）、`ecj.dex`／`d8.dex`＋`d8-2.dex`／`apksigner.dex`（→ d8 转）、`buildtool.dex`（仓库源码 → ECJ → d8）、`ecj-res`（unzip）。
- **「逐字节一致」是 bonus**：本单拿到 2 个（`d8-2.dex`、`buildtool.dex`）；另外 3 个（`ecj.dex` 差 28 B、`d8.dex` 差 28 B、`apksigner.dex` 差 32 B）＝配方相同、参数或原料版本微差，**差异未定位**，不影响可用性（都能跑出同样的版本串／同样的行为）。
- ★**arm64 的 aapt2 只有 Termux 或自己交叉编译两条路**：官方 Google Maven 的 `com.android.tools.build:aapt2` 只有 `linux`／`osx`／`windows` 三个 classifier（实测 8.7.3-12006047：linux=200、osx=200、windows=200；`aarch64`／`android`／`arm64`／`linux-arm64`／`osx-arm64` **全部 404**）；build-tools 37.0.0 zip 里的 `aapt2` 是 **x86-64 Linux ELF**（`/lib64/ld-linux-x86-64.so.2`）。

### 重导配方（★2026-10-13 设备侧实测照抄；命令都跑通过）

```sh
# ── 0) 上游原料（三条）
#  a) Termux 里：pkg install aapt          → 提供 aapt2（aarch64）
#  b) https://dl.google.com/android/repository/build-tools_r37_linux.zip
#     63.1 MB，sha256 01af179347cbcd9c208b7f8171f7b21f6dd1d2f85bcd15e88caa51d5d7b86060
#     → 取 android-37.0/lib/d8.jar（5 个 dex 里 d8/d8-2/apksigner 的来源）、android-37.0/lib/apksigner.jar
#  c) https://repo1.maven.org/maven2/org/eclipse/jdt/ecj/3.13.102/ecj-3.13.102.jar
#     2.6 MB，sha256 e6b938338b7bb12388ca32ba8dfe91c6ab1c56bf5bd8dab6d6e6265fec3b9be3
#  （本机实测：dl.google.com 与 repo1.maven.org 直连可下；若卡住加 curl -4，IPv6 那路会挂）

# ── 1) aapt2 与它的 .so
T=<你的工具链> ; mkdir -p $T/bin $T/dex
cp $(command -v aapt2) $T/bin/aapt2
L=$PREFIX/lib
cp $L/libfmt.so $L/libz.so.1 $L/libpng16.so $L/libexpat.so.1 $L/libprotobuf.so \
   $L/libc++_shared.so $L/libabsl_*.so $L/libutf8_validity.so $T/bin/
cp <platform-35解出来的>/android.jar $T/

# ── 2) 五个 dex（在设备壳里跑；/sdcard 是 noexec → 产物与可执行件放 /data/local/tmp）
D=/data/local/tmp/rebuild ; mkdir -p $D
# 2.1 d8 自己（自举：手上得先有一份能跑的 d8，本仓库说明用的就是现役那份）
env CLASSPATH=$T/dex/d8.dex:$T/dex/d8-2.dex /system/bin/app_process -Xmx1024m /system/bin com.android.tools.r8.D8 \
    --min-api 24 --lib $T/lib/android.jar --output $D/d8 <build-tools>/lib/d8.jar
#    ★内存：1024m 能过；1536m 会被系统 OOM 杀（rc=137）
# 2.2 ECJ（★先解资源，不然编译时会被杀）
mkdir -p $D/ecjres ; unzip -o ecj-3.13.102.jar -x '*.class' -d $D/ecjres
env CLASSPATH=$D/d8/classes.dex:$D/d8/classes2.dex /system/bin/app_process -Xmx1024m /system/bin com.android.tools.r8.D8 \
    --min-api 24 --lib $T/lib/android.jar --output $D/ecj ecj-3.13.102.jar
# 2.3 apksigner（命令行的 jar 只能从 build-tools 拿）
env CLASSPATH=$T/dex/d8.dex:$T/dex/d8-2.dex /system/bin/app_process -Xmx1536m /system/bin com.android.tools.r8.D8 \
    --min-api 24 --lib $T/lib/android.jar --output $D/as <build-tools>/lib/apksigner.jar
# 2.4 buildtool（仓库自带源码）
env CLASSPATH=$D/ecj/classes.dex:$D/ecjres /system/bin/app_process /system/bin \
    org.eclipse.jdt.internal.compiler.batch.Main -source 1.8 -target 1.8 -nowarn -proc:none \
    -classpath $T/lib/android.jar -d $D/btc 工具/BuildTool.java
env CLASSPATH=$T/dex/d8.dex:$T/dex/d8-2.dex /system/bin/app_process -Xmx1536m /system/bin com.android.tools.r8.D8 \
    --min-api 24 --lib $T/lib/android.jar --output $D/btd $D/btc/*.class

# ── 3) 逐个验（跑得出这些串就算成）
LD_LIBRARY_PATH=$T/bin $T/bin/aapt2 version        # → Android Asset Packaging Tool (aapt) 2.20-android-16.0.0_r4
env CLASSPATH=$D/d8/classes.dex:$D/d8/classes2.dex /system/bin/app_process -Xmx512m /system/bin com.android.tools.r8.D8 --version   # → D8 9.2.4-dev (build engineering)
env CLASSPATH=$D/as/classes.dex /system/bin/app_process -Xmx512m /system/bin com.android.apksigner.ApkSignerTool --version         # → 0.9
env CLASSPATH=$D/ecj/classes.dex:$D/ecjres /system/bin/app_process -Xmx512m /system/bin org.eclipse.jdt.internal.compiler.batch.Main -version  # → v20180330-0919, 3.13.102
env CLASSPATH=$D/btd/classes.dex /system/bin/app_process /system/bin BuildTool   # → usage: BuildTool …
```

### 已知差异 / 没验到

- `ecj.dex`、`d8.dex`、`apksigner.dex` 三件重造后与现役**差 28~32 字节**（配方相同、参数或原料版本微差）——**差异未定位**，也不影响可用性；追下去要拿到作者当初用的那一版原料 jar。
- `android.jar` 只做了**指纹比对**，没在本次重新下载官方包解压对比（没必要，指纹已能定到 API 35）。
- Termux 里 `pkg install aapt2`（子包）这条**没在本次真装**——包索引、recipe、二进制可用性均已实测取证，只差装一遍作交叉验证。

## 二、第三方物料（物料/）

| 件 | 从哪拿 | 放哪 |
|---|---|---|
| `classes/*.jar` | AndroidX／AppCompat／Material／Kotlin stdlib／Shizuku-API 等按上游（Google Maven／Maven Central）获取；**`liquidglass-2.0.11.jar`** 自行获取（QWEA0/Liquid-Glass-Android，MIT）；**ML Kit**（`vision-common`、`play-services-tasks` 等，受 ML Kit 条款约束，仓库不分发） | `物料/classes/`（脚本按固定文件名找，自检会逐个点名） |
| `res-zips/*.zip` | 第三方库的资源包（多可从其 AAR 里取 `res/` 打包成 zip） | `物料/res-zips/`（aapt2 link `-R` 用） |
| `jni/<abi>/*.so` | ML Kit 中文 bundled 模型的 native 库（同上，自行获取） | `物料/jni/<abi>/` |
| `manifest碎片/*.xml` | 给第三方库生成 R 类用的包名声明（可选） | `物料/manifest碎片/` |
| `assets/` | 可选 | `物料/assets/` |

## 三、怎么验（两条命令，任跑一条）
