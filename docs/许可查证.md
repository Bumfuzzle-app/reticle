# 许可查证（56 单 · 2026-10-13）

结论先行：**两条拦路虎都查清了 —— 一条能带（但我们选择不把二进制放仓库），一条不能带。**

## 1. Liquid Glass for Android（`liquidglass-2.0.11.jar`）

- 来源：GitHub 项目 **QWEA0/Liquid-Glass-Android**，版本 **v2.0.11**（与构建脚本里 `物料/classes/liquidglass-2.0.11.jar` 同名同版）。
- 许可：**MIT License**（项目 README 与仓库 LICENSE 均标 MIT；可商用，只需保留版权与许可声明）。
- 我们手上的 jar：**只有字节码**，包内仅有 `META-INF/liquidglass_release.kotlin_module`，**没有随包许可文本**，也没法在设备上逐字节核对与上游 release 一致。
- **结论：可以再分发（MIT 允许）**，但本仓库**不放这个 jar**：
  - 仓库只放源码，构建说明（README「构建」节）写明「自行获取 v2.0.11 的 jar 放入 `物料/classes/`」，并注明来源与 MIT；
  - 理由：jar 内无许可文本、无法离线核对来源，放进去反而把「许可归属」这件说不清的事固化在仓库里。
- 若日后要连二进制一起发：需补 MIT 全文＋版权行＋来源 URL，并确认与上游 release 一致。

## 2. Google ML Kit（文字识别，bundled 中文模型）

- 依据：**ML Kit Terms of Service**（https://developers.google.com/ml-kit/terms ，页面标注 Last modified: 2025-05-14）。
  - 原文要点：*"For purposes of these terms, machine learning models will be considered related software."*
  - *"When using the ML Kit APIs, you may not reverse engineer or attempt to extract the source code or any related software, except to the extent that this restriction is expressly prohibited by applicable law."*
  - 该条款并入 Google APIs Terms of Service。
- 解读：模型与相关二进制被明确定义为 "related software"，且禁止提取/逆向。因此**随仓库分发 ML Kit 的 jar/模型 `.so` 不合规**（ML Kit 本身也不是开源许可）。
- **结论：不能带。** 本仓库**不含任何 ML Kit 二进制**（`物料/classes` 下的 ML Kit jar、`物料/jni` 下的 `.so` 都不入库）；README 写明「构建需自行添加该依赖（bundled text-recognition 中文模型）」。
- 附带事实（给用户看的取舍）：用 bundled 模型＝应用内含模型、离线可用、体积大；不 bundled 会依赖 Google Play 服务下载模型，而「没有 Google 服务的机器」本来就用不了——这正是我们选 bundled 的原因。**Reticle 本身不依赖 Google 服务**，只有这一处第三方模型是 Google 的。
